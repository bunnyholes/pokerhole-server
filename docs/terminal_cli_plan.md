# 터미널 CLI 포커 UI 및 방 운영 계획

## 1. 목표 요약
- 최대 4명의 플레이어가 동시에 참여할 수 있는 포커 방 지원
- 텍스트 기반(터미널 CLI) 인터페이스에서 직관적으로 현재 상태를 확인할 수 있는 레이아웃 제공
- 방 생성/입장/퇴장/시작 흐름을 명확히 정의하여 명령 기반 상호작용을 단순화

## 2. 시스템 흐름 개요
1. **방 생성**: 첫 사용자가 `ROOM CREATE <방이름> <닉네임>` 명령으로 방 생성 및 입장
2. **참가자 입장**: 추가 사용자가 `ROOM JOIN <방ID> <닉네임>` 명령으로 참가 (최대 4명)
3. **게임 시작**: 방장(생성자 또는 위임된 사용자)이 `START` 명령으로 라운드 시작
4. **라운드 진행**: 딜러가 자동으로 카드를 분배하고 결과 공지
5. **라운드 이후**: 참가자는 다음 라운드를 기다리거나 `LEAVE`/`QUIT`으로 퇴장

## 3. 터미널 UI 레이아웃 설계
CLI는 최소 **가로 100열 × 세로 32행** 확보를 권장한다. 이 크기에서 다음 배치를 유지한다.

```
┌───────────────────────────────┬────────────────────────────────┐
│ 💰 판돈: 000,000               │ 🕒 2024-05-28 21:35            │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│                          👑 플레이어 A (BTN)                      │
│                      카드: [??][??] | 칩: 10,500                  │
│                                                                   │
│      🧍 플레이어 B (SB)                |             플레이어 C (BB) 🧍 │
│  카드: [??][??] | 칩: 8,250            |        카드: [??][??] | 칩: 12,300 │
│                                                                   │
├─────────────────────────────────────────────────────────────────┤
│      📦 내 보유 칩: 9,750                                            │
│                                                                   │
│                     🂡하트A  🂭다이아Q                               │
│                                                                   │
│   [메시지 로그]                                                    │
│   - 최근 알림을 최대 5줄까지 표시                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 배치 상세
- **좌측 상단**: 현재 판돈(팟) 정보. 고정 폭 영역으로 정렬하여 값 길이에 상관없이 안정적으로 표현
- **우측 상단**: 서버 기준 현재 시간(초 단위 갱신 가능). ISO-8601 또는 `yyyy-MM-dd HH:mm` 포맷 권장
- **상단 중앙**: 테이블 상단에는 버튼/딜러 위치의 플레이어 정보 표시. 이름 옆에 역할(BTN, SB, BB 등) 표기
- **좌중앙 & 우중앙**: 각각 다른 두 플레이어의 정보. 최대 3명의 상대가 존재하므로 남는 슬롯은 `— 빈 좌석 —` 표시
- **좌측 하단**: 내 보유 칩(잔액)
- **하단 중앙**: 내 카드 2장을 유니코드 카드 문자로 강조 표시
- **하단 전체**: 시스템 알림/채팅 로그. 최신 메시지를 아래쪽에 추가하고 5~7줄 버퍼 유지

### 크기 조정 지침
- 메인 프레임은 100×32에 맞추지만, 실제 터미널 너비가 더 넓을 경우 좌우 여백을 추가해 중앙 정렬
- 80열 미만, 28행 미만 환경에서는 "권장 크기 미달" 경고를 표시하고 스크롤형 레이아웃으로 전환할 수 있도록 대비

## 4. 상태 업데이트 전략
- 매 라운드 혹은 명령 처리 후 전체 레이아웃을 재렌더링하여 덮어쓰기 방식으로 최신 상태 표현
- 서버에서 플레이어별 구조체(`PlayerViewModel`)를 구성해 JSON 또는 문자열 템플릿으로 전달
- 클라이언트는 ANSI Escape Code를 사용해 화면을 초기화(`ESC[2J`)한 뒤 커서 위치를 재설정(`ESC[H`)하여 갱신

## 5. 데이터 모델 제안
| 구분 | 필드 | 설명 |
|------|------|------|
| `TableView` | `potAmount` | 현재 판돈 |
|              | `timestamp` | 서버 시각 |
|              | `players` | 최대 4명의 `PlayerSeat` 리스트 |
|              | `localPlayer` | 본인 정보 (`chips`, `cards`) |
|              | `messages` | 최근 알림 문자열 배열 |
| `PlayerSeat` | `nickname` | 플레이어 닉네임 |
|              | `role` | BTN / SB / BB / UTG 등 |
|              | `chips` | 현재 칩 보유량 |
|              | `cards` | 공개 여부에 따라 `[??]` 또는 카드 코드 |

## 6. 방 제어 로직 요약
- 방 정원은 `Dealer.MAX_PLAYER = 4`로 유지
- 방장이 퇴장 시 `participants` 순서 기준으로 다음 참가자를 자동 승급
- 인원 수 변화가 발생할 때마다 `TableView` 재생성 후 전원에게 브로드캐스트

## 7. 추후 확장 아이디어
- 타이머 영역 우측에 라운드 진행 단계(Pre-flop, Flop 등) 표시
- 메시지 로그에 플레이어별 행동(체크, 콜, 폴드)을 색상으로 강조
- JSON 기반 API를 열어 웹 프런트엔드에서도 동일한 배치로 표현할 수 있도록 준비

이 계획을 바탕으로 터미널 환경에서도 직관적인 포커 플레이 경험을 제공할 수 있다.
